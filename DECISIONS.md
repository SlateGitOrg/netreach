# Decisions

Rulings made while building netreach, in the format
`- Ruling: <what> — <why> — <cost if wrong>`.

## Scope and semantics

- Ruling: IPv4 only — AWS security group and NACL semantics are identical for IPv6, but an IPv6 address space needs 128-bit intervals, which would double the interval code for no new reasoning — IPv6-only exposure (for example through an egress-only internet gateway) is invisible to the tool.
- Ruling: A flow is a point in remote IP × protocol × initiator port × service port, and TCP/UDP are the only protocols with ports; every other protocol is pinned to port 0 in both port dimensions — this gives each real flow exactly one canonical point, so set equality is meaningful and the simulator and engine agree on what a "flow" is — ICMP type/code filtering (AWS encodes it in FromPort/ToPort) is not modelled; an ICMP rule matches all ICMP.
- Ruling: Security groups are evaluated as a union of allow rules, and a flow is attributed to the first admitting rule in (group order, rule order) for explanations — AWS has no rule order in SGs, but an explanation must name one rule — when several rules admit a flow, the report names one of them, not all.
- Ruling: NACLs are applied only when a flow crosses a subnet boundary (never between two ENIs in the same subnet) and are evaluated statelessly in both directions, including the return path — this is AWS behaviour and the main reason "the SG allows it but it still fails" — none, provided the snapshot is accurate.
- Ruling: The return path of internet ingress must route back through the same internet gateway (longest-prefix match in the target subnet's route table on the source address) — an asymmetric return (to a NAT, a blackhole, the local route or a peering) drops the connection in practice — a deliberately asymmetric design via an appliance would be reported as unreachable; appliance (ENI/GWLB) route targets are not modelled at all.
- Ruling: The VPC-local route is authoritative; explicit routes more specific than a VPC CIDR are rejected at validation — AWS allows them only for middlebox targets (ENI, gateway load balancer endpoint), which are out of scope — snapshots using middlebox routing cannot be analysed until those targets are modelled.
- Ruling: VPC CIDRs must be unique across a snapshot — it makes "which VPC owns this address" unambiguous; overlapping VPCs cannot be peered anyway — snapshots of unrelated accounts that reuse 10.0.0.0/16 must be split into separate snapshots.
- Ruling: Internet sources are modelled as arriving at the target VPC's internet gateway, whatever their address. A CIDR passed to `-from` is always treated as an internet source; internal sources must be named ENIs or instances — an internal CIDR would need a hypothetical ENI with unknown security group memberships, which makes SG references undecidable — "from this whole subnet" has to be asked per ENI.
- Ruling: Security group references match only when the peer ENI is a member and the referenced group is in the same VPC or a VPC joined by an active peering; for internet flows they never match — this mirrors AWS (cross-VPC SG references work over same-region peering) — cross-region peering (where AWS does not support SG references) is not distinguished from same-region.
- Ruling: Any active peering between the two VPCs satisfies the forward and return route checks; peering is never transitive — AWS routes on the peering ID, but two peerings between the same pair of VPCs are not allowed — none in valid AWS configurations.
- Ruling: Default egress destinations are every address outside the snapshot's VPC CIDRs; destinations routed to `local` or a peering are reported as "internal to the snapshot", not as internet egress — internal reachability is answered by the internal-ingress query instead — an internet destination that happens to fall inside a VPC CIDR elsewhere in the snapshot is excluded from default egress.
- Ruling: A NAT gateway translates only TCP, UDP and ICMP and may pick any source port in 1024-65535, so return traffic must be admitted by the NAT subnet's inbound NACL for every port in that range (a universal quantifier computed with cylindrification) — AWS documents this range and gives no control over the choice; a NACL that admits only part of the range causes intermittent failures, which a per-port check would miss — conservative: a configuration that "works most of the time" is reported as blocked, with the denied ports listed by `why`.
- Ruling: The egress NACL checks between an instance and a NAT gateway are applied only when they sit in different subnets; a NAT in the instance's own subnet is reported blocked at the NAT subnet's route (the route table sends 0.0.0.0/0 back to the NAT) — that configuration is a routing loop in AWS too — none known.
- Ruling: One private IPv4 and at most one public IPv4 per ENI; secondary private IPs and prefix delegation are not modelled — keeps the target a single address — secondary addresses reachable through a different public IP are not analysed.
- Ruling: Load balancers, transit gateways, VPN/Direct Connect, VPC endpoints, firewall appliances and IPv6 egress-only gateways are out of scope — each is a substantial model on its own, and VPCs, subnets, route tables, IGW, NAT, peering, SGs, NACLs and ENIs already cover the paths most exposure mistakes travel — exposure through an ALB/NLB in front of a private instance is not reported (the ALB's own ENI can be analysed if exported as an ENI).

## Representation and algorithms

- Ruling: Interval sets are canonical (sorted, disjoint, non-adjacent) — equality becomes slice equality and every operation is a linear merge — none.
- Ruling: Header spaces are unions of disjoint boxes whose sides are interval *sets* (not single intervals), compacted by merging boxes that differ in one dimension — one SG rule such as "tcp 80,443 from 10.0.0.0/8" stays one box; disjointness makes subtraction exact and membership unambiguous — worst-case box counts are polynomial in the number of rules (see docs/ARCHITECTURE.md); pathological rule sets could be slow, and no resource limit is enforced.
- Ruling: Longest-prefix matching is computed as an ordered partition: routes sorted by descending prefix length each claim their CIDR from the remainder — CIDRs either nest or are disjoint, so this is exactly LPM without per-address work — none.
- Ruling: Fragments (flow classes) are merged when their hop sequences are identical, after every stage — this bounds work by the number of distinct decision paths rather than by box fragmentation — merged fragments lose nothing, since the hop trace is the only per-fragment data.
- Ruling: The reference simulator shares only the compiled model with the engine, and re-implements LPM (full scan), NACL ordering (explicit minimum search), SG semantics and the NAT quantifier (a loop over 64,512 ports) — an oracle that reuses the engine's code would agree with its bugs — the shared compiler is trusted by both; it is tested separately by table-driven validation tests.
- Ruling: Severity grading is a short explicit table (sensitive ports, "broad" = at least a /8 worth of sources) and applies only to internet ingress — transparent and testable rather than clever — it will mis-grade services on non-standard ports; internal and egress results are not graded.

## Engineering

- Ruling: Zero third-party Go dependencies — the domain needs only the standard library, and a security tool benefits from a minimal supply chain — none.
- Ruling: `go.mod` declares Go 1.23 (the code needs 1.22+ for range-over-int and math/rand/v2), but the project was developed and verified only with Go 1.27.1; CI runs both 1.23 and 1.27 — honest about what was actually run — if 1.23 fails in CI, the go directive should be raised.
- Ruling: The coverage gate (85%) is measured over the core packages (interval, hspace, model, engine, sim, report) with `-coverpkg`, so the simulator's coverage comes from the differential and ground-truth tests that exercise it — the simulator has no meaningful unit tests of its own; its correctness is the agreement with hand-derived expectations — none.
- Ruling: One hand-derived probe expectation was wrong on the first run (nat-egress, internet tcp/22 to eni-pubhost: I expected the security group to drop it, but the NACL's implicit deny comes first). The expectation was corrected after re-deriving it by hand from the rules — engine and simulator agreed with each other and with the corrected derivation — this is recorded so the ground truth is not mistaken for engine output.
